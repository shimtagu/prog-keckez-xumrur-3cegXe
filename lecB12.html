25  (12) 機械学習コンペ

東京23区の中古マンションの価格を予測するコンペ

今日の目標

  1. 国土交通省が公開している元のままのデータを読み込み、予測に使える形に自分で前処理できるようになる。
  2. 学習用データを「学習用」と「検証用」に分け、検証用データの RMSE を比べて、予測に使うモデルを自分で選べるようになる。
  3. 選んだモデルでテストデータの価格を予測し、決められた形式の CSV ファイルで提出する。
  4. 第13回に、「どの変数をなぜ使ったか」「前処理で何をしたか」を自分の言葉で説明できるように準備する。
Note

今日の位置づけ

総合分析演習の最後（5回目）です。これまでの4回は「\(X\) は \(Y\) に影響するか」という問いに答えるために回帰分析を使いました。今回は回帰分析を、まだ分からない値を当てる（予測する）ために使います。

今回はコンペ（予測の競争）です。全員が同じデータを使い、テストデータの価格をどれだけ正確に予測できるかを競います。正解の価格は教員だけが持っています。

決められた形式でない予測ファイルは採点できません。行数が 1,000 行でない、欠損（NA）がある、価格が万円になっていない（円のまま、log のまま）などのファイルは、順位の対象外になります。提出する前に、下の「提出ファイルの作り方」のチェックを必ず行ってください。

25.2 今日のデータ

国土交通省の「不動産情報ライブラリ」で公開されている、2025年に東京23区で売買が成立した中古マンションのデータです。不動産会社の仲介で売買が成立したときの価格（成約価格）が記録されています。1行が1件の売買（1つの部屋）です。

出典：国土交通省「不動産情報ライブラリ」（https://www.reinfolib.mlit.go.jp/）の不動産価格（成約価格）情報をもとに、教員が23区・2025年の分を取り出して加工しました。

25.5 予測の考え方

予測の流れ

順番 すること 使うデータ
1 読み込んで、前処理をする 学習用・テストの両方（同じ処理をする）
2 学習用データを、さらに「学習用」と「検証用」に分ける 学習用
3 いくつかのモデルを「学習用」で作り、「検証用」の RMSE を比べる 学習用
4 一番良かったモデルを、学習用データ全体で作り直す 学習用
5 そのモデルでテストデータの価格を予測し、CSV で保存する テスト

テストデータの正解は皆さんには分かりません。そこで、手元の学習用データの一部を「検証用」として取っておき、正解を知っているのに、知らないふりをして予測してみることで、どのモデルが良さそうかを確かめます。

RMSE

RMSE（Root Mean Squared Error、平方根平均二乗誤差）は、予測がどれくらい外れているかを表す数字です。

\[ \text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(\text{実際の値}_i - \text{予測値}_i)^2} \]

外れた大きさ（誤差）を2乗して平均し、最後に平方根をとって元の単位に戻します。今回なら単位は万円で、「予測は平均的に〇〇万円くらい外れている」と読みます。小さいほど良い予測です。

練習：車の燃費を予測する

前期第3回で使った mpg データ（車の燃費）で、予測の流れを確かめます。高速道路の燃費 hwy を、エンジンの大きさ displ と駆動方式 drv から予測します。

library(tidyverse)

df_car <- mpg |>
  mutate(id = row_number())

set.seed(123)
df_learn <- df_car |> slice_sample(prop = 0.8)
df_valid <- df_car |> anti_join(df_learn, by = "id")

nrow(df_learn)
nrow(df_valid)

2
乱数の種を決める。同じ数字にすると、何度やっても同じ分け方になる。
3
80% の行をランダムに選んで「学習用」にする。
4
「学習用」に選ばれなかった残りの 20% を「検証用」にする。 
[1] 187
[1] 47
rmse <- function(actual, pred) {
  sqrt(mean((actual - pred)^2))
}

model_a <- lm(hwy ~ displ, data = df_learn)
model_b <- lm(hwy ~ displ + drv, data = df_learn)

pred_a <- predict(model_a, newdata = df_valid)
pred_b <- predict(model_b, newdata = df_valid)

rmse(df_valid$hwy, pred_a)
rmse(df_valid$hwy, pred_b)
1
RMSE を計算する関数を自分で作る。actual に実際の値、pred に予測値を入れる。
2
2つのモデルを「学習用」だけで作る。
3
predict() の newdata に検証用データを渡すと、検証用データの1行ずつについて予測値が出てくる。
4
検証用データで RMSE を計算する。小さいほうのモデルが良い予測をしている。 
[1] 3.593386
[1] 2.545503
Important

log() を使ったモデルは exp() で元に戻す

lm(log(hwy) ~ ..., data = ...) のように、被説明変数に log() を付けたモデルの predict() は、log の値を返します。RMSE を計算したり提出したりする前に、exp(predict(...)) のように exp() で元の単位に戻してください。戻し忘れると、価格の予測が「8.6」のような小さな数字になってしまいます。

Note

変数を増やせば良いとは限らない

変数をたくさん入れると、学習用データにはよく当てはまるようになります。しかし、学習用データにたまたまあった特徴まで覚えてしまい、新しいデータ（検証用・テスト）では予測が悪くなることがあります。これを過学習といいます。モデルの良し悪しは、必ず検証用データの RMSE で判断しましょう。

25.6 データを読み込むときの注意

文字コード

配布した CSV ファイルは、ダウンロードしたときのまま Shift-JIS（CP932）という文字コードで保存されています。read_csv() は何も指定しないと UTF-8 という文字コードとして読むため、日本語が文字化けしたり、エラーになったりします。前期の期末レポート（SSDSE）と同じように、locale で文字コードを指定して読み込みましょう。

df_train_raw <- read_csv("tokyo_train.csv",
                         locale = locale(encoding = "CP932"))

tokyo_test.csv も同じように読み込みます。

日本語の列名

列名に「：」や「（）」が入っているので、R のコードの中で使うときは `最寄駅：距離（分）` のようにバッククォート（`、Shift + @ キー）で囲む必要があります。最初に rename() で英語の短い名前に変えておくと、あとのコードが書きやすくなります。

25.7 テストデータの前処理で気をつけること

Important

テストデータの行は1行も消さない

提出する予測は、テストデータの 1,000 件すべてについて必要です。学習用データでは、欠損のある行や極端な値の行を filter() や drop_na() で除いて構いませんが、テストデータの行を消すと、その分の予測が出せなくなります。

  • 学習用データで作った変数（単位を変えた価格、築年数、log をとった変数など）は、テストデータにも同じ方法で作ってください。モデルに入れた変数がテストデータにないと、predict() がエラーになります。
  • テストデータにも空欄（NA）がある列があります。モデルに入れた変数が NA の行は、予測値も NA になり、採点できなくなります。テストデータで空欄がないか確かめてから、使う変数を選びましょう。

25.8 提出ファイルの作り方

提出する CSV ファイルは、submission_sample.csv と同じ形にします。

列名 内容
id テストデータの id（100001〜101000）
price 予測した価格（万円）

submission_sample.csv は、1,000 件すべてに学習用データの平均価格（7,504万円）を入れた例です。最後に、作った予測を write_csv() で保存します。ファイル名は submission_学籍番号.csv にしてください（例：submission_25X0001.csv）。

Important

提出する前のチェック

保存したファイルを read_csv() で読み込み直して、次の4つを確かめましょう。

  1. 行数が 1,000 行か（nrow()）
  2. 列名が id と price の2つか（names()）
  3. price に NA がないか（sum(is.na()) が 0 か）
  4. price が万円の単位になっているか（summary() で、数千〜数万の値になっているか。円のままなら数千万、log のままなら 10 前後の値になる）

25.9 ベースライン

予測がうまくできているかの目安として、ベースライン（基準になる簡単なモデル）を決めておきます。

ベースライン：学習用データから、徒歩の分数・建築年が分からない行を除き、lm(価格（万円） ~ 面積 + 築年数 + 徒歩の分数) で予測したもの。

このベースラインのテストデータでの RMSE は 約 4,456 万円です。これより小さい RMSE を目指しましょう。

25.10 本日のレポート

今回の assignmentB12.qmd には、5つのステップの見出しだけが書かれています。パッケージやデータの読み込みも含めて、何をどの順番で書くかを自分で考えてレポートを完成させましょう。

レポートの条件

  • 予測する変数（被説明変数）は、価格（万円）。円から万円への変換は自分で行う。
  • 学習用データを「学習用」と「検証用」に分け、ベースラインを含めて3つ以上のモデルの検証用 RMSE を表にまとめて比べる。
  • 一番良かったモデルを学習用データ全体で作り直し、テストデータの価格を予測して、提出用の CSV ファイルを作る。
  • ステップ5では、どの工夫で RMSE が小さくなったか（ならなかったか）と、その理由を書く。

提出方法：① 予測の CSV ファイル（submission_学籍番号.csv）と、② Render して出力された HTML ファイルの ZIP を、Blackboard から提出してください。提出期限は1月15日（金）24時です。提出は1回だけです。

Important

第13回は、提出したレポートを画面に映しながら、一人ずつ内容を説明してもらいます。「この変数をなぜ使ったか」「このコードは何をしているか」「テストデータにはどんな前処理をしたか」と質問されても答えられるように、自分で理解したコードだけを書きましょう。生成 AI に質問するのも構いませんが、出てきたコードは自分で理解してから使ってください。

25.11 ヒント

困ったときは、該当するヒントを開いてください。まずは自分の力で考え、どうしても進めないときに開くようにしましょう。

Tip読み込みのヒント
  • 文字コードの指定は、上の「データを読み込むときの注意」を見てください。
  • 読み込んだら glimpse() で列の型を確かめましょう。数字のはずの列が <chr>（文字）になっていたら、その列に数字以外のものが混じっています。
  • 全部が空欄の列は <lgl> という型で読み込まれます。中身はすべて NA です。
Tip前処理のヒント（数字にする）
  • 学習用データの 最寄駅：距離（分） には、数字ではない値が混じっています。count() で値の一覧を見てみましょう。
  • 文字の列を数字にするには as.numeric() を使います。数字にできない値は NA になり、警告（Warning）が出ます。
  • 「2005年」のように数字と文字が混じった値から数字だけを取り出すには、parse_number() が使えます。
  • 築年数は、今回の売買の年（2025年）から建築年を引いて作れます。
Tip前処理のヒント（どの行を除くか）
  • 学習用データで、使う変数が NA の行は除きましょう。
  • 価格のヒストグラムや、面積と価格の散布図を描いて、ほかと比べて極端な値の行がないか確かめましょう。極端な値の行は、回帰直線を大きく引っぱることがあります。除くかどうか、除くならなぜかをレポートに書きましょう。
  • テストデータの行は消してはいけません（上の「テストデータの前処理で気をつけること」）。
Tipモデルを工夫するヒント
  • どんな部屋が高く売れるかを考えてみましょう。広さ、古さ、駅からの近さ、場所（区）などが思い浮かびます。
  • 価格のヒストグラムを描くと、右に長く伸びた形になっています。前期第9回（相関分析）で、1人あたり GDP に log() を使って散布図を描いたことを思い出し、log() を使うと形がどう変わるかを見てみましょう。
  • 「面積が同じでも、区によって価格の上がり方が違うのでは？」と思ったら、前期第12回の交差項が使えます。
  • 変数を増やしたら、必ず検証用データの RMSE が小さくなったかを確かめましょう。
Tip予測と提出のヒント
  • predict(モデル, newdata = テストデータ) で、テストデータの1行ずつの予測値が出てきます。
  • tibble(id = テストデータの id, price = 予測値) で提出用の表を作り、write_csv() で保存します。
  • log() を使ったモデルは、exp() で戻すのを忘れずに。
  • 保存したら、上の「提出する前のチェック」を必ず行いましょう。
