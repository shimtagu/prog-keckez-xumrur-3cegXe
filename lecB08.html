21  総合分析演習3

「学区ごとの学力テスト」のデータを分析する

今日の目標

  1. 与えられたデータを見て、自分で問いと仮説を立てる。
  2. 元のデータにない変数（1人あたりの数や平均点）を mutate() で作り、その単位に注意して係数を読めるようになる。
  3. 記述統計・可視化・単回帰・重回帰を使って、5つのステップのレポートを一人で完成させる。
  4. 次回、自分のレポートの内容（Rコード含む）を自分の言葉で説明できるように準備する。
Note

今日の位置づけ

総合分析演習の3回目です。進め方はこれまでと同じで、2回で1セットです。今日（第8回）に分析してレポートを書き、次回（第9回）にその内容を説明します。前回（第7回）に説明の順番を待つ間に始めた分析の続きから取り組みましょう。

第4回のデータは「1行が1つの授業」、第6回は「1行が1人の働く人」でした。今日のデータは「1行が1つの学区（地域）」です。生徒一人ひとりの点数ではなく、学区ごとにまとめた数字が入っています。

21.1 総合分析演習の進め方

回 授業ですること 授業のあとにすること
第8回（今日） データを読み、問いと仮説を立て、assignmentB08.qmd で分析してレポートを書く レポートを仕上げて提出する
第9回（次回） レポートの内容を、教員に一人ずつ説明する（約5分）。自分の番を待つ間に、総合分析演習4のデータを受け取って分析を始める 総合分析演習4の分析を進める
Important

提出期限

レポート（assignmentB08.qmd を Render した HTML の ZIP）の提出期限は、次回の授業開始（11月30日 15:45）までです。これ以降は提出できず、レポートを提出していないと次回の説明もできません。

評価：総合分析演習1回分（15%）は、提出したレポートと、次回の説明の内容をあわせて評価します（5つのステップ × 3段階＝15点満点）。

21.2 自分で問いを立てる

今日のデータでは、被説明変数はテストの平均点（score）に決まっています。ただし、score はデータに入っていないので、読解の平均点（read）と数学の平均点（math）の平均として、自分で作ります。皆さんが決めるのは、

  1. テストの平均点に影響しそうな主な説明変数 \(X\) を1つ
  2. \(X\) とテストの平均点の両方に影響しそうなコントロール変数を2〜3個

です。問いの立て方、仮説に理由をつけること、コントロール変数の選び方は、これまでと同じです。

Important

今日の条件

主な説明変数とコントロール変数のうち、少なくとも1つは、元の変数から計算して自分で作った変数（教員1人あたりの生徒数など）を入れてください。作り方と注意点は、下の「元のデータから新しい変数を作る」で説明します。

21.3 今日のデータ

アメリカのカリフォルニア州で、1998〜1999年度に行われた州の学力テストの結果と、学区ごとの学校・家庭の状況をまとめたデータです。テストを受けたのは小学5年生です。学区（school district）は、いくつかの公立学校をまとめて運営する地域の単位で、日本の市町村の教育委員会にあたります。

今日のデータ（CASchools.csv）

1行が1つの学区です。420の学区が入っています。

変数名 内容
rownames 行の番号（分析には使わない）
district 学区の番号（分析には使わない）
school 学区の名前（分析には使わない）
county 学区がある郡（county、日本の「県の中の地域」にあたる）。45種類
grades 学区の学校の範囲：KK-06（幼稚園〜小学6年）/ KK-08（幼稚園〜中学2年）
students 生徒数（人）
teachers 教員数（人）。常勤に換算した人数なので、小数になる
calworks 州の生活保護（CalWORKs）を受けている家庭の生徒の割合（%）
lunch 給食費の補助（無料・割引）を受けている生徒の割合（%）
computer コンピュータの台数（台）
expenditure 生徒1人あたりの教育支出（ドル）
income 学区の住民の平均所得（千ドル）
english 英語を学んでいる途中の生徒（英語が母語でない生徒）の割合（%）
read 読解テストの平均点
math 数学テストの平均点
Note

割合の変数は 0〜100 の %

calworks・lunch・english は 0〜100 の % で記録されています。たとえば english が 10 なら「生徒の10%が英語を学んでいる途中」という意味です。回帰分析の係数は、「割合が1ポイント（1%分）高い学区は、平均点が〇点高い（低い）」と読みます。

また、income の単位は千ドルなので、1 増えると「平均所得が1,000ドル高い」という意味になります。

21.4 今日の準備

前回（第7回）にすでに準備した人は、そのフォルダで続けてください。

1. 新規 R プロジェクトを作成する。Directory name は「LessonB08」、場所は Kドライブの「R_programming」。
2. Blackboard から CASchools.csv・assignmentB08.qmd をダウンロードし、「R_programming/LessonB08」フォルダに入れる。
3. まずは氏名（学籍番号）を記入し、この状態で Rendering ができるか確認する。
4. 左側に Rendering して出力された画面を置き、右半分には RStudio を置いて assignmentB08.qmd でレポートを書く。
5. 適当なところで Rendering し、確かめながら進める。

大学の PC はシャットダウンするたびに初期化されるため、毎回インストールが必要です。

21.6 元のデータから新しい変数を作る

今日のデータには、生徒数（students）・教員数（teachers）・コンピュータの台数（computer）のように、数で記録された変数があります。数の変数は、学区が大きいほど大きくなるので、そのままでは「学区が大きいか小さいか」を比べているだけになってしまいます。そこで、前期第2回で学んだ mutate() を使い、割り算で「1人あたり」の変数を作ってから比べます。

下の例は、架空の4つの町の「人口」と「図書館の本の冊数」と「図書館の予算」のデータです。

library(tidyverse)

df_town <- tibble(
  town   = c("A町", "B町", "C町", "D町"),
  people = c(2000, 8000, 5000, 10000),            # 人口（人）
  books  = c(10000, 24000, 20000, 20000),         # 本の冊数（冊）
  budget = c(3000000, 9000000, 6000000, 8000000)  # 予算（円）
)

1人あたりの変数を作る

df_town <- df_town |>
  mutate(books_per_person = books / people)

df_town
1
本の冊数を人口で割って、住民1人あたりの冊数を作る。 
# A tibble: 4 × 5
  town  people books  budget books_per_person
  <chr>  <dbl> <dbl>   <dbl>            <dbl>
1 A町     2000 10000 3000000                5
2 B町     8000 24000 9000000                3
3 C町     5000 20000 6000000                4
4 D町    10000 20000 8000000                2

本の冊数（books）だけを見ると、B町（24,000冊）が一番多く、A町（10,000冊）が一番少なく見えます。しかし、1人あたりの冊数（books_per_person）で比べると、A町が 5冊で一番多く、D町が 2冊で一番少なくなります。何で割るかによって、比べている中身が変わることに注意しましょう。

単位をそろえる

予算（budget）は円の単位なので、数字がとても大きくなります。このまま回帰分析に入れると、係数は「予算が1円多いと…」という意味になり、とても小さな値になって読みにくくなります。そこで、割り算で単位を変えておくと、係数が読みやすくなります。

df_town <- df_town |>
  mutate(budget_man = budget / 10000)

df_town |>
  select(town, budget, budget_man)
1
円を1万で割って、万円の単位にする。 
# A tibble: 4 × 3
  town   budget budget_man
  <chr>   <dbl>      <dbl>
1 A町   3000000        300
2 B町   9000000        900
3 C町   6000000        600
4 D町   8000000        800
Important

作った変数を回帰分析に入れたら、係数は作った変数の単位で読みます。たとえば books_per_person の係数なら「住民1人あたりの本が1冊多いと…」、budget_man の係数なら「予算が1万円多いと…」です。レポートには、どの変数をどう計算して作ったか（何を何で割ったか、単位は何か）を必ず書きましょう。

Note

作った変数が正しいか確かめる

mutate() で作った変数は、元の変数と並べて表示し、いくつかの行を電卓で計算して合っているか確かめましょう。第4回・第6回でダミー変数を作ったときに count() で件数を確かめたのと同じ考え方です。

21.7 本日のレポート

今回の assignmentB08.qmd には、5つのステップの見出しだけが書かれています。パッケージやデータの読み込みも含めて、何をどの順番で書くかを自分で考えてレポートを完成させましょう。第4回・第6回の自分のレポートを見返すと、各ステップで何をしたかを思い出せます。

レポートの条件

  • 被説明変数は、読解（read）と数学（math）の平均点（score）。mutate() で自分で作る。
  • 主な説明変数1つと、コントロール変数2〜3個を自分で選ぶ。そのうち少なくとも1つは、元の変数から計算して自分で作った変数にする。
  • 単回帰分析と重回帰分析を行い、modelsummary で並べて表示する。

提出方法：Render して出力された HTML ファイルを ZIP 形式に圧縮して Blackboard から提出してください。提出期限は次回の授業開始（11月30日 15:45）までです。

Important

次回は、提出したレポートを画面に映しながら、一人ずつ内容を説明してもらいます。「このコードは何をしているか」「この変数はどう計算したか」「この係数はどういう意味か」と質問されても答えられるように、自分で理解したコードだけを書きましょう。分からないところは、遠慮なく手を挙げて質問してください。生成 AI に質問するのも構いませんが、出てきたコードは自分で理解してから使ってください。

21.8 ヒント

レポートを書いていて困ったときは、該当するステップのヒントを開いてください。まずは自分の力で考え、どうしても進めないときに開くようにしましょう。

Note

Render が止まったときは

Render の途中でエラーが出ると、HTML は作られません。Background Jobs（または Render）タブのエラーメッセージに出ているチャンクの名前（label）を確認し、そのチャンクのコードを直してから、もう一度 Render しましょう。ステップを1つ終えるごとに Render すると、どこでエラーが出たのかすぐに分かります。

Tipステップ1のヒント（問い）
  • まず「今日のデータ」の変数の表を見て、テストの平均点に影響しそうな変数を探しましょう。
  • rownames・district・school は番号や名前なので、説明変数にはしません。county は45種類もあるので、今回は説明変数に入れないでおきましょう。
  • read と math は score を作るのに使うので、説明変数にはしません。
  • 自分が通っていた小学校・中学校を思い出し、「どんな学校（地域）だと点数が高くなりそうか」を考えてみましょう。
Tipステップ1のヒント（仮説とコントロール変数）
  • 仮説は「\(X\) が〜な学区ほど、テストの平均点が高い（低い）」という形で、予想される符号（＋ か −）とその理由を書きます。
  • コントロール変数は、「主な説明変数が違う学区は、ほかの点でも違っていないか？」と考えて選びます。たとえば、お金に余裕のある地域とそうでない地域では、学校の条件も家庭の条件も違うかもしれません。
  • calworks・lunch・income は、どれも「家庭の経済状況」に関係する変数です。似た変数を同時にたくさん入れると、係数が読みにくくなることがあります。
Tipステップ2のヒント
  • 作った変数ごとに、「何を何で割ったか」「単位は何か（人、台、ドル、千ドルなど）」を書きましょう。
  • 割り算で作った変数の値が小さすぎる（大きすぎる）ときは、「100人あたり」「千ドルあたり」のように単位を変えると、係数が読みやすくなります。
Tipステップ5のヒント
  • 仮説が「支持された」と言えるのは、係数の符号が予想と同じで、かつ p 値 < 0.05 のときです（第3回）。
  • 問いへの答えは、「〜な学区ほど、テストの平均点が〜。その関係は、〜をコントロールしても残る（残らない）」のように、係数の大きさ（点）も入れて書きます。
  • 今日のデータは学区ごとの平均です。学区について分かったことが、生徒一人ひとりにもそのまま当てはまるとは限りません。
